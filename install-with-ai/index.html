Install with AI: from one opaque prompt to a recommended toolkit

Prototype · Natalie Friedman · August 2026 · Reconstructions on the current production Install SDK page, not screenshots
Hypothesis. Users skip the install prompt for two reasons. They can't tell it will install a guide that runs their whole onboarding, so hand-prompting feels safer (it isn't, their agent lacks account access and current API knowledge). And a "skill" is a strange front door; installing an MCP server is the familiar act. The fix in every option below: tell users plainly that this is the recommended path, show what each tool is and does, and make each install one click or one paste.
Today BASELINE
What ships now: one prompt that adds the onboarding skill, a short bullet list, two doc links. The control for any test.
Option 1: toolkit checklist 3 TOOL CARDS
Three tool cards (MCP server, onboarding guide, CLI) with what/why, one-paste installs, inspect links, and ticking checkmarks. Kickoff prompt comes after the tools.
Option 2: one command, fully transparent SMALLEST CHANGE
Keeps today's single paste but the prompt describes outcomes, a callout answers "why not just ask my agent", and a disclosure lets skeptics inspect all three tools.
Option 3: MCP-first, three steps TESTS ENTRY POINT
Step 1 is the familiar act: add the MCP server, with a per-agent picker and one-click installs. The skill becomes "the playbook" in step 2. CLI optional in step 3.
Option 4: show the plan, one CTA EXPECTATIONS UPFRONT
The page shows the exact five-step plan the agent will follow (tools are steps 1 and 2), then a single "Copy the kickoff prompt" button. Verify line maps to step 5.
Every page has a "Why this option" button in the bottom switcher with the rationale and the risk. The +23% figure is the real April result for guided vs manual First SDK Connected.
