Foundation plan picker: where should the AgentControl-only choice live?

Natalie Friedman · Sep 17 2026 · Interactive reconstruction of the in-app Plans page as a trialist sees it. Copy and plan versions come from gonfalon plan data on main.

The problem

Trialists see an Add CodeControl switch above the plan cards. It frames feature flags as the add-on and AgentControl as the core product, on the page where most trialists came for flags. Turning it off silently changes the Foundation card to a different plan while the name and price headline stay the same.

It exists because pricing requires AgentControl to be purchasable standalone, and Billing implemented that as a page-level switch that picks between two Foundation plan versions (Megan Heskett, Jun 3 to 16 2026, PRs 64130, 64234, 64832; spec was the Lovable billing prototype).

What the switch actually does

CardSwitch ONSwitch OFF
DeveloperFull copyAgentControl copy only. Same free plan, features hidden.
Foundationv3: flags + AgentControl + observabilityv4: AgentControl + observability. Flags capped at free tier. Monthly billing only.
GuardianFull copyAgentControl copy only. Same plan, features hidden.

Only the Foundation card changes what you buy. No event tracks the switch, and the purchase event has no version, so we cannot see how often trialists choose v4.

What "AgentControl only" really is

  • Not a cheaper plan. AI runs cost the same on both versions: 5,000 free, then $5 per 1,000. Service connections from AI-only environments never count on any plan (pricing DACI), so a pure AgentControl team pays the same on the full platform.
  • It is a spending guardrail. v4 keeps flags on the free tier so flag usage can never create a charge. The trade: monthly billing only, and flags go read-only past 5 service connections or 1,000 client-side MAU.
  • One-way door. v4 to full platform is allowed any time. Full platform back to v4 is blocked in code (support only). Existing Foundation customers can never pick v4.
  • Relevant to a small minority of trialists. In the last 60 days, 411 of 4,745 welcome-survey completers (8.7%) said AI was the first thing they wanted to do; 57% said flags.

Recommendation

  • Ship C now. Delete the switch for trial and Developer viewers, render every card as full platform, and move the choice into Customize plan as a two-option picker with the infomark below. Default full platform. Frontend only, reuses the version storage that already exists.
  • Instrument it. Add a version property to the plan-selected and purchase events, and a picker-changed event, so v3 vs v4 demand is measurable for the first time.
  • Land D when Jeremy's resolver scoping ships. At that point most trialists never see the picker because the catalog returns one Foundation. The picker only renders when two Foundation versions come back.
  • Leave the existing-customer flow alone. Foundation v1/v2 customers see "Add AgentControl", a different job (upgrade to v3) reached from the AgentControl opt-in page.
  • Decide this week. Jeremy is porting the switch-dependent copy into backend YAML for the config-driven picker (spec dated Sep 9). Eric's spec currently keeps the switch as-is; changing where the choice lives is a scope add he needs before flag-on.
