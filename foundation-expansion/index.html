Foundation expansion: suggest the next product at the moment it solves a problem

Prototype · Natalie Friedman · August 2026 · Reconstructions on current production pages, not screenshots · Mechanics verified against the product codebase
Premise. 99% of Foundation customers use flags only, even though Experimentation, Observability (including Session Replay), and a starter allowance of Guarded Rollouts are in the plan they already pay for. Interruption marketing won't move them; the play is to catch the moment when the adjacent product solves the problem in front of them, the value is self-evident, and the friction is provably low (we detect their SDK, their telemetry, and their tracked events before suggesting).

The ladder. The three products adopt in an order: telemetry first (one config block at install time), because it auto-creates the error metrics that make a guarded rollout zero-setup, and guarded rollouts teach the metric-plus-rollout mechanics that make a first experiment a small step instead of a leap. Every moment below nudges one rung.

2. Design prototypes: end-to-end flows

Click-through walkthroughs: every screen from trigger to done, including the branches. Use the arrows or dots in the dark bar, and the "Why this moment" button for design decisions and gating.
Flow A: experiment from a flag rollout EXPERIMENTATION
Moments 1 and 2 as the entries → one-field create modal (flag and rule attach automatically) → design page checklist that leads with events they already send → prefilled metric → honest start confirmation → running. Includes the no-events branch, the only path that needs code.
Flow B: first guarded rollout GUARDED ROLLOUTS
Moment 5 as the entry: mode picker with the 5-included disclosure → form where the auto-created error metric is already waiting → review with the allowance stated → monitoring → regression with evidence and three explicit choices → rollback story plus the ladder nudge.
Flow C: observability setup OBSERVABILITY
Both entries walked in one flow: Moment 6 (install checkbox) and Moment 3 (the Monitoring blind spot on a live rollout) land in the same setup with environment and language preselected → a designed waiting state → the connected moment that names what lit up → the filled page that pays off the pitch.
Flow D: metric from an event METRICS
Moment 4 as the entry: config-derived banner → their events ranked → prefilled create-metric modal → a success state that previews exactly where the metric appears next (Experiment and Guarded options with METRIC READY chips).

The moments (single-screen concepts)

The original trigger-surface concepts the flows grew from.
Moment 1: experiment card on a fresh rollout EXPERIMENTATION
The user builds a 25/75 percentage rollout. Before it serves anyone, an inline card in the targeting canvas offers to start it as an A/B test on the same audience, included in their plan. Fresh rollout means clean results; this is the moment to measure, not later. → Walked end to end in Flow A (entry, step 1)
Moment 2: experiment offer in the save confirmation EXPERIMENTATION
Same offer as Moment 1, but as a save-confirmation modal after they commit. They just took a measurable risk in production; peak motivation, higher intrusion. A/B these two placements. → Walked end to end in Flow A (alternate entry)
Moment 3: observability setup when a rollout goes live OBSERVABILITY
The account has zero telemetry (like 99% of Foundation customers), and a rollout just went live. The Monitoring page shows evaluations climbing next to empty error and session panels: real users are on the new experience and nothing shows what they see. One setup fills the page in. → Walked end to end in Flow C (entry 2, step 2)
Moment 4: add-metrics nudge on the flags list METRICS
A config-derived banner says the quiet part: 3 recent rollouts split traffic and nobody measured the outcome. The fix is forward-looking: create a metric from an event they already send (two clicks, no code), so the NEXT release starts as an A/B test or guarded rollout. Deliberately not retroactive: users on running flags are already exposed, so converting those mid-flight would give muddy results. → Walked end to end in Flow D (step 1)
Moment 5: guarded rollout allowance in the mode picker GUARDED ROLLOUTS
Every account includes 5 guarded rollouts and nothing in the product says so until the allowance is half gone. A Recommended tag and one inclusion line in the rollout mode picker the user already sees, with the auto-created error metric pre-selected when telemetry exists. → Walked end to end in Flow B (step 1)
Moment 6: observability checkbox at SDK install OBSERVABILITY
The single lowest-friction moment: the user is already in their init file. One checkbox extends the install snippet with the o11y plugins, and unlocks Moments 3 and 5 downstream. Precedent: the experimentation snippet checkbox already shipped on this page. → Walked end to end in Flow C (entry 1, step 1)
